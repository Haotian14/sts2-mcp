# 跨角色策略层 + 开局复盘（6.3b）设计

2026-08-01

两件事合成一份设计，因为它们是同一个闭环的两半：策略层规定「据什么做判断」，
开局复盘规定「这一局的判断从上一局的哪些事实出发」。

---

## 1. 背景与动机

`docs/strategy.md` 现有的七节全部来自 2026-08-01 的连续实跑（力士两局、静默一局），
每条结论都带实战证据。问题是**它读起来是两个角色的实战记录，而不是一套可迁移的判据**：

- §5 的「优先拿降费/回能的牌」举的是放血、战鼓、遗忘仪式——全是力士的牌，
  换角色就无从对应
- §6 的商店结论举的是无情猛攻、血墙
- §1 的机制条目（斩杀优先、击晕线、荆棘顺序）**其实与角色无关**，
  只是例子取自那两个角色，于是也被误读成角色专属

同时 `spec.md` 的 6.3b 一直没做：「开新局前复盘上一局」。它没做的原因不是难，
而是**全靠自觉**——每次开新局都急着往下打，没人回头读日志。
`logs/decisions.jsonl` 至今积了 781 条、5 局，一次都没被开局时读过。

## 2. 已定的取舍

| 问题 | 决定 | 理由 |
|---|---|---|
| 没实战过的角色，内容从哪来 | **只抽机制层，角色节留空槽** | 守住「只收录实战验证过的判断」这条铁律。反编译卡池能立刻铺满文档，但会让文档第一次出现大量未验证内容，而这份文档的全部价值就在于读的人能信它 |
| 「压成短提示」由谁压 | **代码递硬事实，模型写教训** | 与 6.5 的结论一致：日志的价值全在理由上，理由得由做决定的人写。模板拼出来的建议写不出「为什么」，会退化成套话 |
| 通则与实战记录怎么摆 | **原地重构 `strategy.md`** | 单一真相源。「结论 + 紧跟证据」也正是 `spec.md` 已有的行文风格 |
| 通则按什么轴组织 | **骨架按决策时刻，构筑一节内部按作用类型** | 决策时刻是**实际查文档的时机**（`auto_run` 交还时说的就是「路线决策交还」）；而角色差异只在构筑处爆发，用作用类型收口 |

## 3. `strategy.md` 重构

### 3.1 目标骨架

```
# 决策策略
   铁律不变：只收录实战验证过的判断
   新增：正文是跨角色通则，牌名一律只作括号里的例子；
         角色专属结论一概进 §6

§0  开局：先复盘上一局              新增，6.3b 的落点
§1  战斗 · 出牌                     原 §1，机制层，牌名降格为例子
§2  战斗 · 什么时候必须停手         原 §3，整节搬移
§3  构筑：决定一局上限              核心重写，按作用类型
      3.1 优先级：引擎件 > 降费/回能件 > 单卡伤害数字
      3.2 引擎件：怎么认、什么时候铺
      3.3 降费/回能件：怎么认
      3.4 缩表：除卡与「不拿牌也是一种拿」
      3.5 升级选谁
      3.6 商店买什么（数据仍只有一次，须标明）
      3.7 休息点：烤火还是打铁
§4  路线与资源                      原 §2
§5  算伤害用 values，不用卡面       原 §4，纯机制，不动
§6  角色档案
      6.1 力士（已验证）
      6.2 静默猎手（验证中）
      6.3+ 其他角色：标题 + 「尚无实战数据」一句，打过再填
§7  待验证
```

§1 / §2 / §4 / §5 是搬位置与换例子，判据一个字不改——它们本来就是机制层。
**§3 是唯一真正重写的一节。**

### 3.2 §3 的抽象方式

原文那句「优先拿降费/回能的牌，其次才是伤害数字」实际上混了两条。抽象后：

> **构筑优先级：引擎件 > 降费/回能件 > 单卡伤害数字**
>
> - **引擎件**：每回合自动产出、且产出随回合数增长的东西
>   （静默：涂毒——每次未格挡攻击叠中毒，升级后 2 层）
> - **降费/回能件**：把「一回合能打出几张牌」抬上去的东西
>   （力士：放血 0 费回 3 能、战鼓、遗忘仪式）
> - **单卡伤害**：只提高单次投送量的攻击牌
>
> **判据**：三局都倒在同一个算式上——每回合约 14 点、Boss 222 血需要约 15 回合，
> 而我方只撑得住约 8 回合。单卡伤害提高的是分子；引擎件与降费件改变的是**算式本身**。

牌名退成括号里的例子，判据本身不含角色。

### 3.3 证据保留

原文那几段血的教训**全部保留**，紧跟在对应通则下面：

| 证据 | 归到 |
|---|---|
| v1 启发式在 HP 37/70 面对四怪时全灭 | §2 必须停手 |
| 第一章 Boss 战差 5 点没跨过击晕线 | §5 用 values 不用卡面 |
| 两局分别差 16 / 33 血倒在 Boss | §3.1 构筑优先级 |
| 能量优先的第三局第一次打过 Boss | §3.1 构筑优先级 |

这些段落的信息量全在「当时的数字」上，压缩即失效。

### 3.4 角色档案节的形状

每个角色一节，只写**本角色已实战验证**的内容：核心件叫什么、走过什么构筑路线、
死于什么。没打过的角色只留标题与一句「尚无实战数据」——不留空标题，
因为空标题会被误读成「这里本该有内容而漏了」。

⚠️ **角色名单尚未核实**。本项目至今只见过力士与静默猎手两个角色，
v0.107.1 一共有几个角色没有查过——`Screens.cs` 是从角色选择界面**读**出按钮的，
名单不在代码里。故本次只建 6.1 / 6.2 两节，其余等下次经过角色选择界面时
照实抄一份名单再补，**不凭印象预先列出**（一代的角色名单不能假定二代照搬——
Boss 遗物三选一那次就是这么错的，见 spec.md §3.4g）。

## 4. 6.3b：开局复盘

### 4.1 组件

两个小工具，各只做一件事：

**`get_brief()`（只读）**

从 `logs/decisions.jsonl` 抽出**上一局**的硬事实，不生成任何建议：

```
run          上一局的标识、角色、天梯层数
ended        是否已结束
died_floor   结束于第几层第几幕；死时血量（取自 kind=run_end 那条）
stops        停手点按界面分组的计数，外加最后若干条停手理由
builds       构筑决策清单：在奖励/三选一/商店/休息点上做的动作及当时的 why
plan         上一局开局时写下的计划（若有）
```

**`set_plan(plan)`（只写）**

把模型读完事实后写下的「这一局据此改什么」记进日志，`kind="plan"`。

`digest()` 现有的筛选规则是「带 `kind` 的一律留」，因此 plan 天然会出现在
下一局的 `get_brief()` 里——**闭环不需要额外代码**。

### 4.2 数据流

```
开新局
  └→ auto_run 发现「本局第 1 层且本局尚无 plan」→ 停手交还
       └→ 模型调 get_brief()      得到上一局的硬事实
       └→ 模型自己写教训
       └→ 模型调 set_plan(...)    记进日志，kind=plan
            └→ auto_run 再跑就不再因这条停手
                 └→ 本局结束，plan 连同 run_end 一起留在日志里
                      └→ 下一局的 get_brief() 读到它
```

### 4.3 为什么要在 auto_run 里加这个停手点

6.3b 拖到今天没做，恰恰因为它全靠自觉。这个项目已有的办法就是
「该做决策的地方让 runner 停下来」——开局计划是整局里价值最高的决策
（strategy §3：构筑决定一局上限），它理应和卡牌三选一一样有一个停手点。

不改地基，只多一个停手点：判据是 `run.total_floor <= 1` 且本局日志中无
`kind=plan` 的记录。

### 4.4 边界情况

| 情况 | 行为 |
|---|---|
| 日志为空（第一次跑） | `get_brief()` 返回 `{"run": null}`，不报错；auto_run 仍停一次手，模型写一句「无上一局可复盘」即可 |
| 上一局没结束（中途换了角色） | 照样给事实，`ended=false`，`died_floor` 用见过的最大层数 |
| 只有 menu 桶 | 视同没有上一局 |
| 日志文件损坏/半行 | 沿用 `_read_all()` 的既有行为：跳过坏行，不抛 |
| 存在 `#2` 后缀的同秒局标识 | 按日志中的出现顺序取，不解析标识本身 |

### 4.5 错误处理

沿用 `journal.py` 的铁律：**日志是旁路，游戏才是主线**。
`get_brief()` / `set_plan()` 内部一切异常吞掉并降级（返回空 / 静默不记），
绝不让复盘功能把一步已下发的动作变成失败回报。

## 5. 测试

`test_journal.py` 新增：

- 空日志 → `get_brief()` 返回空结构，不抛
- 只有 menu 桶 → 视同无上一局
- 正常一局 → 抽出 `died_floor`、停手分组、构筑决策清单
- 上一局无 `run_end` → 降级为「见过的最大层数」，`ended=false`
- `set_plan` 写入的条目能被 `digest()` 保留，并出现在下一局的 `get_brief()` 中

`test_autorun.py` 新增：

- 第 1 层且本局无 plan → 停手，理由含「复盘」
- 第 1 层但已有 plan → 不因此停手
- 非第 1 层且无 plan → 不因此停手（半局接手时不该被这条拦住）

## 6. 不做的事

- 不反编译各角色卡池写进文档（见 §2 的取舍）
- 不把 strategy.md 复制成一套 prompt 模板——spec.md 6.3b 原文已判过：
  它会很快与原文漂移
- 不让代码生成任何「建议」文本
- 不改 `auto_combat` 与安全线判据这些地基
